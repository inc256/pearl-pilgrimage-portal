# Project File Summary

This document summarizes the main files and folders in the `pearl-pilgrimage-portal` project, including their responsibilities and how they connect. It is intended to help Copilot or any developer quickly identify which files are relevant for a task without scanning the entire repository.

## Root Files

- `package.json`
  - npm package metadata and scripts.
  - Defines dependencies (`react`, `react-router-dom`, `@supabase/supabase-js`, `@tanstack/react-query`, etc.) and dev dependencies (`vite`, `typescript`, `vitest`, `eslint`, `@playwright/test`).
  - Key scripts: `dev`, `build`, `preview`, `lint`, `test`.

- `vite.config.ts`
  - Vite build and development server configuration.
  - Likely includes path aliases and plugin setup for React.

- `tsconfig.json`
  - TypeScript compiler configuration.
  - Global options and includes for the project.

- `tsconfig.app.json`
  - App-specific TypeScript settings.
  - Usually extends the base `tsconfig.json` and configures build paths.

- `tsconfig.node.json`
  - Node-specific TypeScript configuration for tooling and scripts.

- `eslint.config.js`
  - ESLint configuration for linting the project.
  - Ensures consistent code style and catches issues before build or commit.

- `tailwind.config.ts`
  - Tailwind CSS configuration.
  - Defines theme extensions, content paths, and animation rules.

- `postcss.config.js`
  - PostCSS configuration that typically enables Tailwind CSS and autoprefixer.

- `index.html`
  - Base HTML entrypoint for the Vite app.
  - Contains the root DOM node where React mounts.

- `README.md`
  - Project documentation entrypoint.
  - May include setup instructions, feature overview, and deployment notes.

- `bun.lock`, `package-lock.json`
  - Dependency lockfiles.
  - `bun.lockb` is likely created by Bun if used or present from a prior install.

- `playwright.config.ts`
  - Browser automation and end-to-end test configuration for Playwright.

- `playwright-fixture.ts`
  - Custom Playwright fixtures, likely used by tests to provide reusable setup.

- `components.json`
  - Metadata for component scaffolding, likely generated by the UI component library tooling.
  - Helps manage the `src/components/ui` library structure.

## Public Assets

- `public/robots.txt`
  - Static file for web crawler rules.
  - Served directly by Vite and included in the production build.

## Source Directory: `src/`

### App Entry and Styling

- `src/main.tsx`
  - Application bootstrap.
  - Imports `App` and `index.css`, then mounts React into `#root`.

- `src/App.tsx`
  - App root component.
  - Wraps application with providers:
    - `QueryClientProvider` from React Query for server-state management.
    - `TooltipProvider` for tooltips.
    - `Toaster` and `Sonner` for toast notifications.
  - Defines routing using `react-router-dom`.
  - Renders page-level components for each route and includes the global `WhatsAppButton`.

- `src/index.css`
  - Global CSS styles for the application.
  - Likely includes Tailwind directives and global UI resets.

- `src/App.css`
  - Additional component-specific styles for the app portion.
  - Used alongside `index.css` if there are app-level CSS classes.

- `src/vite-env.d.ts`
  - Type definitions for Vite-specific imports and environment variables.

## File Relationships and Connectivity

- `src/main.tsx` -> mounts `src/App.tsx` -> loads app providers and routes.
- `src/App.tsx` -> Route definitions for all page files under `src/pages/`.
- Page components -> compose shared components from `src/components/`.
- Shared components -> use `src/components/ui/` primitives for buttons, dialogs, forms, etc.
- `src/pages/FAQ.tsx` -> likely reads from `src/data/faqs.json` and renders `FAQSection.tsx`.
- `src/components/NavLink.tsx` and `src/components/Navbar.tsx` -> handle navigation and route links.
- `src/lib/supabase.ts` -> initialized Supabase client used by `src/hooks/useSupabase.ts`.
- `src/hooks/use-toast.ts` -> interfaces with `src/components/ui/toast.tsx` or `sonner`.
- `src/hooks/use-mobile.tsx` -> provides viewport awareness for components that need responsive logic.
- `src/lib/packageUtils.ts` -> supports package display components like `HajjPackage.tsx`, `Packages.tsx`, and `UmrahPackages.tsx`.

## How to Use This Summary for Task Scoping

- For routing and page-level tasks: inspect `src/App.tsx` and the `src/pages/` folder.
- For UI styling and reusable components: inspect `src/components/` and `src/components/ui/`.
- For data access or backend integration: inspect `src/lib/supabase.ts`, `src/hooks/useSupabase.ts`, and `src/types/supabase.ts`.
- For state/query handling: inspect `src/App.tsx` plus `@tanstack/react-query` usage.
- For tests: inspect `src/test/` and `playwright.config.ts` / `playwright-fixture.ts`.
- For build and lint configuration: inspect `package.json`, `vite.config.ts`, `tsconfig*.json`, `eslint.config.js`, `tailwind.config.ts`, and `postcss.config.js`.

## Notes

- The `src/components/ui/` folder is a shared component primitives library that most app UI relies on.
- `src/pages/` contains full-screen route targets, while `src/components/` contains reusable pieces that may appear on more than one page.
- `src/lib/` and `src/hooks/` contain application logic and integration helpers rather than UI.
- This summary assumes a typical React + Vite + Tailwind + React Router architecture.
